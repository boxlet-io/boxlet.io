Bring your app as it is.

Boxlet isn't an SDK you rewrite your app against. It's a build tool and an engine: the build turns the Go or Rust app you already have into WebAssembly, and the engine runs it beside your containers.

In development. Each part below says whether it's designed, tested or already a standard.

Inside boxlet build

An app doesn't fail as WebAssembly because of your code. It fails in a few places underneath it, and they're the same places for every app. So the build fixes them once, at the root.

  1. Search the tree

    Every package the app is built from. A production Go API we searched had 731: 50 of its own, 419 from 103 library modules, and 262 from Go's standard library.

  2. Swap Go's network code

    22 of those library modules open connections themselves: the web framework, the Postgres, Redis and Mongo drivers, WebSockets and more. All 22 go through one place, Go's net package. The build swaps that one place with Go's own -overlay flag, so your folder, go.mod and module cache stay untouched.

  3. Add missing files

    Some libraries have no WebAssembly version of one small function. The Postgres driver lib/pq looks up the system's user name, which WebAssembly doesn't have. The build adds that one file.

  4. Check for blockers

    cgo, running other programs, or work that needs many cores. If the app's code actually reaches one, it's built as a container, and you're told the file and line.

$ boxlet build ./...
searched   731 packages
network    22 library modules, through the engine
added      lib/pq: user lookup
blockers   none reached from main
built      api, as a boxlet

The engine's doors

WebAssembly can't open a socket, read a file or see the system by itself. It reaches the machine only through doors the engine hands it, and it gets only the doors you grant.

Your code callsThe engine
e.Start(":8080")Opens the real port on the machine and hands the boxlet a handle to it.
gorm.Open(postgres.Open(dsn))
redis.NewClient(opts)		Looks up db or cache, makes the real connection and hands it back. The drivers keep speaking Postgres and Redis.
http.Get("https://…")The same, plus the trusted certificates HTTPS needs.
os.ReadFile("migrations/0001.sql")Only from the folders you grant.
os.Getenv("DATABASE_URL")The settings you pass in, and no others.

One engine per machine, not a sidecar per app. The engine is shared by every boxlet on the machine. A helper process next to each app would cost a few megabytes each, which is the cost we removed by dropping the container.

Long-running or per request. A server with a scheduler and background workers stays running as one boxlet. A handler can start for each request and be gone after it.

One Compose file for both kinds

The app is built as a boxlet when it can be, and the databases stay containers. They share one network, so db and cache mean the same thing to both.

services:
  api:
    build: .                  # Go: a boxlet if it can be
    ports: ["8080:8080"]
    environment:
      DATABASE_URL: postgres://app@db/app
      REDIS_URL: redis://cache:6379
  db:
    image: pgvector/pgvector:pg17  # a container
  cache:
    image: redis:7            # a container

A build tool, not an SDK

Most WebAssembly platforms give you an SDK: you rewrite your app against their interfaces before it runs. That's the step that keeps most teams on containers. Boxlet does the work in the build instead, so the app you have is the app you ship.

A boxlet is a standard WebAssembly component, so one that uses only standard interfaces runs on any WebAssembly engine. Go apps are the exception for now: until Go builds for the newer WASI with real sockets, their network doors are Boxlet's own, and they need Boxlet's engine.

What we've checked so far

Each result below is from a test we ran, not from the plan.

What we triedWhat happened
A Go hello world, unchangedRuns 2.4 MB as WebAssembly.
A Go web server, unchangedNeeds the doors It builds and starts, but nothing can connect to it. Go's WebAssembly build uses a pretend network inside the program.
Calling another API or a databaseNeeds the doors Fails today for the same reason: no real network.
Swapping Go's network code in the buildWorks The unchanged server's call to open its port reached our code.
A production Go API, 731 packagesNeeds one file It doesn't compile yet: the Postgres driver's user lookup is missing.
Size of the Go web serverTrade-off 10.7 MB as WebAssembly against 6.0 MB as a native program. Go boxlets save memory, not disk.

Tested on 22 November 2026 with Go 1.27.1 and Wasmtime 51 on an Apple silicon Mac. Limits that stay for now: one CPU core per boxlet, about 4 GB of memory, and no running other programs. Go changes its network files between releases, so the swap has to keep up with each one.
